# Ken LLM gateway

Private localhost service using the official `codex app-server` stdio protocol and existing **ChatGPT login**. It does not extract cookies/tokens or call undocumented ChatGPT web endpoints. The account must have Codex access; requests consume Codex plan limits. This is a local prototype, not a public inference API.

```text
Android → backend Java → codex-chatgpt provider → localhost gateway → Codex → model
                      → openai / ollama / existing providers
```

## Run

Python 3.11+ and `aiohttp` are required (`requirements.txt`). Log in once with `codex login` on the machine running the gateway. `codex login status` must show ChatGPT. The current development CLI is the bundled desktop binary; override `KEN_CODEX_CLI` when installing elsewhere.

From the project root:

```sh
python services/llm-gateway/local.py start
python services/llm-gateway/local.py models
python services/llm-gateway/local.py smoke
python services/llm-gateway/local.py configure-backend
python services/llm-gateway/local.py status
python services/llm-gateway/local.py stop
```

`configure-backend` writes only the dedicated, owned `robotai_ken` schema. It creates one tagged config and preserves existing defaults if present. It refreshes this gateway's token/URL on rerun. Restart the Java services after using it to clear cached configuration. No database migration is needed: it uses the existing provider field/factory.

The local manager creates `.local/llm-gateway.json` (permissions 0600), containing a random **internal gateway token**, not an OpenAI API key. It is used as `sys_config.apiKey` solely to authenticate Java → gateway. Never share or commit this file. Runtime stderr/access logs contain no prompts or auth tokens. Log: `.local/llm-gateway.log`.

## Backend configuration

| Field | Value |
|---|---|
| provider | `codex-chatgpt` |
| apiUrl | `http://127.0.0.1:8787/v1` |
| apiKey | Internal gateway token generated by the local manager |
| configName | `codex-default`, or a model returned by `/v1/models` |
| modelType | `chat` or `vision` |
| enableThinking | false → `low`; true → `medium` |
| contextLength | 4096 suggested for short conversations |

The management UI now lists this provider. `codex-default` selects the account's default available model; unavailable explicit names return 400, never silently change models. OpenAI-compatible and Ollama providers retain their original settings and credentials. Role `modelId` chooses a config; a null role model uses the existing default-selection mechanism.

This adapter supports text and **one inline JPEG/PNG image** per request. Java removes runtime tool callbacks/context for this provider. Gateway rejects tool messages, tools, external image URLs, JSON response formats and embeddings. Select another provider for function calling or embeddings. `temperature`, `top_p`, `max_tokens` / `max_completion_tokens`, `stream_options` are accepted for Spring AI compatibility but are not mapped to Codex; generated output is bounded by the turn timeout, not by an exact token cap. Gateway accepts reasoning effort supported by the selected model. Request timeout is 90 seconds by default.

## HTTP contract

All endpoints require `Authorization: Bearer <internal-token>`:

- `GET /health`: process health and busy flag (does not validate login).
- `GET /v1/models`: checks login and returns current available models.
- `POST /v1/chat/completions`: text `messages`, or user content parts containing text and an inline `image_url` data URL, `model`, `stream`, optional `reasoning_effort`. `/chat/completions` is an alias.
- Streaming: OpenAI-compatible SSE `choices[].delta.content`, final `finish_reason=stop`, then `[DONE]`. Stream failure sends an `error` event without successful `[DONE]`; HTTP status cannot change after headers were sent.
- Client disconnect: cancel handler, send `turn/interrupt`, terminate request's app-server process. A remote interrupt is best effort; there is no guarantee it reverses already consumed quota.
- At most two generating requests at a time, each in its own isolated process. This allows background memory compression alongside a voice turn. Further requests return 429 with Retry-After. Invalid payload/model returns 400, auth 401, upstream/login/timeout before streaming 503.

Limits: 100 messages / 32000 text characters / 3 MiB body / one image of at most 2 MB. Images are written with mode 0600 in a private request directory, supplied as Codex `localImage` input, and deleted on success, failure, timeout or disconnect. No remote URL fetching or user-supplied filesystem paths. Backend owns history and trims it before calling. No persistent Codex chat history: ephemeral thread and separate private temporary cwd/process for each request. No automatic LLM retries or provider fallback.

## Isolation and limitations

The gateway disables each configured MCP transport (`enabled=false`, verified via `config/read`), plugins/apps/hooks/shell/unified execution/browser/computer use/subagents and other capability flags. Each thread and turn sets `environments=[]`, no workspace/capability roots, no dynamic tools, read-only sandbox, and never approvals. Any server tool request is denied; non-chat items abort the turn. Existing global login remains managed by the official CLI; its normal auth refresh/state writes may still occur.

Validated with bundled Codex **0.159.0-alpha.12.1**. Empty environments are experimental protocol fields: an incompatible CLI must fail rather than silently enable capabilities. Verify the isolation tests and model catalog after updates. Bind is deliberately `127.0.0.1`: Java and gateway must run on the same host; this version does not expose an unauthenticated LAN service or provide a multi-user account pool.

A separate process per request prioritizes isolation and reliable cleanup, with additional startup overhead. Live Vietnamese samples on this Mac: **TTFT 5.72 s, total 6.18 s** initially; **TTFT 6.27 s, total 6.61 s** after verifying mandatory isolation gates. See the current acceptance report in `docs` for Android STT → LLM → TTS results and remaining physical-phone checks.

## Tests

```sh
PYTHONPATH=services/llm-gateway python -m unittest discover -s services/llm-gateway/tests -v
```

Java adapter tests: `CodexChatGptModelProviderTest`. `KEN_LLM_LIVE=1` enables its opt-in real gateway test (consumes a Codex turn); otherwise it uses a fake SSE HTTP service.

References: [official app-server protocol](https://learn.chatgpt.com/docs/app-server), [official authentication](https://learn.chatgpt.com/docs/auth). The originally linked [codex-with-chatgpt](https://github.com/XiaoDuoYa/codex-with-chatgpt) is a read-only workspace MCP bridge, not an inference gateway, so it is not the runtime dependency for this service.
